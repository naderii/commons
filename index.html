    کتابچه راهنمای مدیر سیستم لینوکس¶

    راهنمای عملیاتی برای مدیریت، نگهداری، امنیت و عیب‌یابی سرورهای لینوکس

    مرجع موضوعی برای مدیران سیستم، کارشناسان شبکه و تیم‌های عملیات — هر دستور با کاربرد، روش بررسی، خطرات و مسیر بازگشت.

    شروع از مبانی برگه تقلب

    bash · نمونه خروجی
    $ uptime up 41 days, load 0.42 $ systemctl --failed 0 loaded units listed. $ df -hT / /dev/sda2 ext4 58G 21G 35G 38% / $ # همه‌چیز سالم است

    الان رخداد دارید؟¶

    دیسک پر شده سرویس بالا نمی‌آید سرور کند است شبکه قطع است OOM / کمبود حافظه SSH قفل شده مشکوک به نفوذ

    اصل اول: قبل از هر اقدام، شواهد را ذخیره کنید (scripts/incident-snapshot.sh را اجرا کنید) و سپس کم‌خطرترین اقدام را انجام دهید.

    چطور از این کتابچه استفاده کنیم¶

    این کتابچه فقط لیست فرمان نیست. هدف این است که:

    • قبل از اجرا بدانید چه چیزی و چرا تغییر می‌کند
    • بعد از اجرا بتوانید نتیجه را تأیید کنید
    • در صورت مشکل، مسیر بازگشت (Rollback) داشته باشید
    • تفاوت توزیع‌ها (Debian/Ubuntu، RHEL/Rocky، Alpine و …) را در نظر بگیرید

    راهنمای نمادها¶

    نماد معنی
    بدون تغییر فقط می‌خواند؛ اجرایش روی سرور زنده بی‌خطر است
    تغییر وضعیت سیستم را عوض می‌کند؛ پنجرهٔ تغییر، بکاپ و راه برگشت لازم است
    مخرب می‌تواند داده یا دسترسی را از بین ببرد؛ دوبار بررسی و تأیید لازم است
    SERVER_IP، SERVICE، USER نام با حروف بزرگ جایگزین‌شدنی است؛ هرگز عیناً کپی نکنید
    192.0.2.x، 198.51.100.x، example.com آدرس‌های مستند (RFC 5737 / RFC 2606)؛ نمونه‌اند، نه آدرس واقعی
    sudo یعنی فرمان نیاز به دسترسی بالا دارد؛ قبل از آن بدون sudo (فقط‌خواندنی) تست کنید

    کارهای پرتکرار — نقطهٔ شروع بررسی¶

    نیاز فرمان‌های شروع راهنمای مرتبط
    سلامت کلی سرور uptime · free -h · df -hT · nproc کارایی سیستم
    سرویس‌های ناموفق systemctl --failed · systemctl status SERVICE پردازش‌ها و سرویس‌ها
    پورت‌های در حال شنود sudo ss -lntup شبکه
    خطاهای اخیر یک سرویس journalctl -u SERVICE -b -n 200 --no-pager لاگ و عیب‌یابی
    فضای دیسک و inode df -hT · df -ih · du -xh /path \| sort -h دیسک و فایل‌سیستم
    وضعیت کانتینرها docker ps -a · docker compose ps Docker
    رزولوشن DNS getent hosts example.com · dig +short example.com وب، DNS و TLS
    اتصال SSH ssh -v USER@HOST SSH
    فایروال sudo ufw status verbose یا sudo nft list ruleset امنیت و فایروال
    بار پردازشی top -o %CPU · ps aux --sort=-%cpu \| head کارایی سیستم
    ورودهای مشکوک last -a \| head · sudo lastb \| head امنیت و فایروال
    بکاپ سالم است؟ restic snapshots · sha256sum -c SHA256SUMS پشتیبان‌گیری

    اصول ایمنی قبل از هر تغییر¶

    قبل از اجرای فرمان‌های مخرب

    ابتدا میزبان، محیط (prod / staging) و اثر دستور را بررسی کنید.
    فرمان‌هایی مانند rm -rf، mkfs، dd، lvremove، iptables -F، nft flush ruleset و docker system prune --volumes می‌توانند داده را حذف یا سرویس را قطع کنند.

    چک‌لیست حداقلی (به همین ترتیب):

    1. هویت محیط: hostnamectl + cat /etc/os-release — روی کدام سرور هستم؟ (اسم میزبان را در prompt ببینید.)
    2. وضعیت فعلی: خروجی فقط‌خواندنی را ذخیره کنید (systemctl status، df -h، ss -lntup)
    3. پشتیبان / Snapshot: قبل از تغییر فایل‌سیستم یا تنظیمات حساس
    4. مسیر بازگشت: بدانید چگونه تنظیم را برمی‌گردانید — و تست‌شده باشد
    5. پنجرهٔ تغییر: در production بدون هماهنگی تغییر ندهید
    6. دسترسی جایگزین: کنسول / IPMI / نشست دوم SSH باز باشد (به‌ویژه برای فایروال، SSH و شبکه)

    روش استفاده از کتابچه¶

    1. موضوع را از منوی بالا، کارت‌های صفحهٔ اصلی یا جست‌وجو انتخاب کنید (جست‌وجو فارسی و انگلیسی را می‌فهمد).
    2. جدول «راهنمای سریع» اول هر فصل را بخوانید؛ ستون ریسک را جدی بگیرید.
    3. فرمان را در محیط آزمایشی یا با دسترسی محدود اجرا کنید.
    4. خروجی و وضعیت سرویس را بررسی کنید — «بدون خطا» همیشه به معنی «سرویس سالم» نیست.
    5. در production قبل از تغییر، فایل پیکربندی و وضعیت فعلی را ثبت کنید.

    هر قطعه کد دکمهٔ کپی دارد. بلوک‌های کدی که فقط «نمونه» هستند با کامنت # نمونه مشخص شده‌اند.

    دربارهٔ این پروژه¶

    این کتابچه بر این باور بنا شده که دانش وقتی ارزشمندتر می‌شود که به اشتراک گذاشته شود و تجربهٔ امروز، راهنمای فردای دیگران باشد. با فلسفه و فرهنگ دانش مشترک این مجموعه آشنا شوید.
